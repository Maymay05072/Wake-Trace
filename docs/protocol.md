# 最终结果协议

完成可选的工具调用后，一次醒来必须以一个 JSON 对象结束：

```json
{
  "outcome": "trace",
  "fact": "通过可信工具读取了当前天气。",
  "content": "雨很轻，我在这里多待了一会儿。",
  "share": "",
  "residue": "也许下一次还会想起雨落下来的声音。",
  "next_wake": {
    "min_minutes": 45,
    "max_minutes": 90,
    "reason": "暂时没有需要立刻继续的事情。"
  }
}
```

## 不变量

- `outcome` 只能是 `silent`、`trace` 或 `message`；
- `message` 必须提供非空的 `share`；
- `silent` 不允许携带 `share`；
- 缺失、截断或无效的 JSON 对象属于失败；
- `fact` 必须简短并描述事件，不能复制整段表达性正文；
- `residue` 始终覆盖上一条而不是追加，并会自动过期；
- 运行时可以因重复消息或静默时段阻止推送，并把本次结果降为 `trace`；
- 模型提出的醒来区间始终受到宿主配置的上下限约束。

## 为什么不用控制标记

早期实现曾使用正文中的方括号标记表达状态、事实、推送内容和下一次醒来时间。标记容易被模型漏写、
截断、重复或当成普通文字输出。

WakeTrace 改用严格 JSON 协议，使“没有输出”“主动静默”和“格式失败”成为三种可以可靠区分的状态。
