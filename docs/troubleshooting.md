# 运行状态与问题排查

手机不能输入终端指令时，打开醒间 Web 的导航 → **运行状态**。先在设置保存后端地址和只读 Web 令牌。
“刷新状态”只读取数据，不调用模型、工具或推送。此页需要支持 `/world/diagnostics` 的新版后端。

## 先区分几种状态

| 页面状态 | 含义 | 下一步 |
| --- | --- | --- |
| 静默 | 这次成功返回了 `silent` | 查看完整行径的缘由、正文和真实工具记录 |
| 留痕 | 私人经历，或消息因策略或发送失败保留为私人经历 | 需要时查服务日志中的 `notification_reason` |
| 联系 | 模型选择联系且通知器报告成功 | 实际收取仍以对应渠道为准 |
| 执行失败 | 请求、输出或协议处理未成功 | 查看页面给出的安全错误原因 |
| 尚未结束 | 数据库没有完整结束记录 | 可能正在执行，也可能服务重启中断；不是静默 |

“最近执行记录”包含最近二十次尝试；行径时间线主要展示成功保存的经历，两者数量不一定相同。
查看页面时不会自动修复历史记录，旧版本未保存的错误细节也无法补回。

## 一直静默

1. 在运行状态中确认是成功的 `silent`，还是执行失败。
2. 到完整行径查看醒来缘由。始终是“自由醒来窗口”说明这些唤醒没有领取到新的外部事件，
   不能据此断言模型或调度器坏了。
3. 确认真实对话是否通过 `waketrace_handoff_chat` 显式“交回生活”。需开启 `WAKETRACE_MCP_ALLOW_WRITE`。
   Kelivo 里的聊天、人设和工具不会自动同步到后端。
4. 如果预期它读取外部记忆或日历，请在后端配置对应 MCP，并明确允许相应工具。只在提示词写工具名字不会获得能力。

接入外部工具不保证每次调用，也不应通过强制发消息掩盖请求失败。

## 没有收到消息

静默、私人留痕本来就不通知。`message` 还会经过重复检查、通知静默时段和真实通知器。
内置 Web 是行径查看器；没有 Web Push 私钥、订阅或自定义通知器，消息无法自动送达聊天客户端。
配置检查只展示 Web Push 的私钥填写与订阅数量，不会发送测试通知；自定义通知器请查对应渠道。

新版日志中的 `notification_reason` 可区分：

| 原因 | 含义 |
| --- | --- |
| `not_requested` | 模型选择静默或私人留痕 |
| `duplicate` | 与上次发送内容近似重复 |
| `quiet_hours` | 当前处于通知静默时段 |
| `delivery_failed` | 通知器没有报告成功送达 |
| `sent` | 通知器报告发送成功 |

## 醒来次数少或时间间隔长

核对页面的后端时区、日间间隔、夜间最短间隔和每日成功醒来上限。夜间最短间隔可超过日间上限。
通知静默时段只影响发送，不等于关闭唤醒。

检查服务是否连续运行、是否发生重启，以及最近是否有失败。“本进程未运行调度器”只说明当前 API 进程：
`waketrace serve` 本来就不启动调度器；分开部署还需运行 `waketrace run`，一体部署用 `waketrace start`。
如果明确由外部客户端负责醒来，则按 MCP 外部醒来协议检查，不必开启内置调度器。
最近调度检查时间在执行唤醒期间可能暂不更新；它不是独立的存活探针。

## 外部 MCP 没调用

| 页面状态 | 检查方向 |
| --- | --- |
| 未配置 | JSON 文件路径与 `WAKETRACE_EXTERNAL_MCP_CONFIG` 是否正确，文件是否在后端容器里 |
| 等待首次发现 | 首次唤醒时才发现工具，本页不会触发连接 |
| 最近连接失败 | 鉴权、网络、连接方式和超时；发现失败最早 60 秒后的下一次唤醒重试 |
| 部分工具未找到 | 允许列表需填服务原始工具名；修改列表后重启重新发现 |
| 最近连接成功 | 只是最近一次发现或调用成功，不代表模型必须调用或下一次连接必定成功 |

SSE 和 Streamable HTTP 按提供方说明选择，不能只根据 URL 后缀猜测。配置在后端生效，不是 Kelivo 的 MCP 设置。
失败的工具调用不会自动重放，避免重复写入。完整配置见 README 的“接入外部 MCP 工具”。

## 模型请求失败

页面会区分请求超时、连接失败、HTTP 错误、空或截断回复以及最终 JSON 格式错误。
HTTP 200 只代表模型 HTTP 请求成功，不能证明返回协议正确。基础配置已填写也不等于接口能调用成功。

模型地址、模型标识、API 密钥与提供方要求逐项核对。旧版数据库或自定义错误中不在安全列表内的原因会显示为
“其他错误”，避免把原始错误中的密钥、URL 或正文展示到网页。

## 提供可排查的信息

点击“复制诊断信息”，或展开文本框手动复制。诊断包括版本、后端时区、调度配置、执行状态与安全错误码，
不包含密钥、模型或外部 MCP 地址、聊天、醒来正文、工具参数或结果。服务别名可能由你自定义，分享前仍可自行检查。

若仍需要日志，提供一次完整唤醒对应的 `cycle_id`、开始、完成或失败日志；不要发送 `.env`、数据库或密钥。
使用二改仓库时，另提供仓库与实际部署的提交版本，避免把最新版源码和仍在运行的旧版本混为一谈。
