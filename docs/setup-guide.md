# 首次配置与手动验证

打开 Web 的“设置”，手机端先点右上角导航。填写 WakeTrace 地址、只读 Web 令牌，保存后往下查看
“首次配置引导”。“检查服务地址”只验证公开 `/health`；能访问服务不代表令牌有效，清单成功加载才说明
具有读取权限。清单本身不会请求模型、发现远程工具或发通知。

## 检查清单

1. **唤醒模型**：在服务器环境变量或 `.env` 中填写 `WAKETRACE_API_BASE_URL`（完整 Chat Completions
   地址）、`WAKETRACE_MODEL` 和 `WAKETRACE_API_KEY`。网页只报告是否填写，不显示密钥或接口地址。
2. **名称与时区**：`WAKETRACE_COMPANION_NAME`、`WAKETRACE_USER_NAME` 供后端唤醒使用；
   `WAKETRACE_TIMEZONE` 按所在地填写，例如 `Asia/Shanghai`。网页上方的“小机名称”仅控制网页显示。
   默认名称、UTC 时区都可以运行，请按实际需求调整。
3. **通知渠道（可选）**：内置 Web Push 需要私钥、联系邮箱、推送依赖和订阅。Python 安装
   `pip install -e '.[webpush]'`；Docker 已包含该依赖。订阅必须由接收消息的宿主 PWA 创建，经管理员
   `POST /subscriptions` 提交；本项目的行径网页不会自行注册订阅。自定义通知器按自己的渠道配置。
4. **外部 MCP（可选）**：按 README 设置 `WAKETRACE_EXTERNAL_MCP_CONFIG`，为服务列出允许的工具。
   状态来自最近一次唤醒时的发现，不是当前网络检测；未接入时内置工具仍可使用。

修改服务器配置后重启服务，再点击“刷新清单”。本页不会代写 `.env` 或 Zeabur 环境变量。

## 手动测试

输入 `WAKETRACE_ADMIN_TOKEN`，再选择一个按钮。Web 令牌或 MCP 令牌不能执行测试。管理员令牌不会写入
localStorage/sessionStorage，点击后输入框立即清空，下一次测试需重新输入。只在自己可信的服务网页输入。

- **测试模型**：发送一次固定短文本请求，不带聊天、行径、工具或唤醒提示；最多请求 128 个输出 token，
  会消耗 API 额度。成功只说明收到兼容的普通文本响应，不保证工具调用或最终醒来 JSON 协议可用。
- **发送测试通知**：向已配置通知器发送明确标注的测试消息；不经过静默时段和重复拦截，因此请在适合
  接收测试消息的时间点击。成功表示渠道接受，仍需到接收端确认；终端通知器只输出到服务日志。

两项互相独立，不创建醒来周期、行径或事实，不修改每日唤醒计数、最近分享和下次计划。每项每分钟最多
一次（跨进程），失败也计入冷却；不自动重试。前端超时或离开页面不保证后端已停止，先查看实际结果。
通知器仍可能清理失效订阅；同一 Web Push 通知器可能发送到多个已登记设备。

## 阅读完整行径

电脑端选中行径后查看右侧详情；手机端选中后点击“查看完整行径”。依次展示：

1. 保存的醒来缘由。
2. 真实工具调用的成功／失败及摘要，不返回工具原始结果。
3. 模型原本选择的结局、最终保存的结局，以及经历和事实。模型自述不等于已验证的工具行为。
4. 通知状态和原拟发送的消息。重复拦截、静默时段和渠道失败都可以导致“联系”降为“留痕”。

此版本不自动补送。旧行径可能没有保存原选择或通知原因，网页会明确显示缺失；不会依据今天的时区或
配置猜测过去。详情读取失败时可点“重试详情”，不要把读取失败当成没有工具记录。

复制“运行状态”的诊断信息仍不含私人正文。完整行径、名称和拟发送消息属于私人内容，分享截图前请自行检查。
